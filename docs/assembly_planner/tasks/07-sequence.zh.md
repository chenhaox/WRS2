# 07：装配序列和支撑资源搜索

状态：待实施。前置：05、06 已整合。

## 目标和修改范围

构建 assembly-by-disassembly 搜索，输出有几何路径和静力证据的装配候选；正向机器人执行仍交给 08。

负责 `sequence.py`、`tests/assembly/test_sequence.py`。测试使用真实的小型几何组合以及可控 evaluator 验证搜索逻辑，不引入神经网络或重新生成 contact 几何。

## 实施步骤

1. 固定状态定义：剩余零件、每件当前 pose、支撑/夹持及资源占用、装配体朝向；如果搜索只支持固定装配体朝向，要明确限制。
2. 定义 remove、acquire support、release support 等动作及前置条件。先做单件拆除，不把所有子装配成组组合都放进首版搜索空间。
3. 先实施确定性、有预算的 DFS，再增加 beam/排序配置。使用外露程度、局部方向和接触数量作候选排序；实际可行性由 05/06 验证。
4. 验证动作前、动作过程中和动作后支撑。不能只检查移除后的静态子装配而忽略释放/接管瞬间的悬空；本阶段的抽象支撑动作保存待机器人细化的需求。
5. 完整状态 key 去重并缓存评估；超时/unknown 可随预算增长重试。冻结障碍或 pose 变化后旧 negative cache 不能继续生效。
6. 拆卸序列反转为装配候选时，同时转换路径方向和支撑事件，重验正向阶段的几何与静力约束，标记 `execution_validated=False`。
7. 输出 schema 化状态链、动作、对象路径、支撑需求、代价组成和每个失败原因。没有证明的搜索策略不宣称最优或全局无解。

## 验收

- 小装配有已知顺序约束，输出顺序满足约束且 replay 每步通过 05/06。
- 同一零件集合但不同 pose/辅助夹持产生不同状态；不能被错误去重。
- 拆除一件导致其余件不稳时，需要支撑或拒绝；资源不足不能生成计划。
- 支撑切换不能瞬时释放全部支持，反转序列后仍有正确事件顺序。
- 有限预算返回 exhausted/unknown；固定 seed/排序产生可重复序列。
- 默认不把“几何+平衡候选”标记成“机器人已可执行”。
