## 当前几何案例：6500 个固定球面点

采样方式与教学网页相同：中点形式的 z 坐标、固定黄金角；不特别添加球极点。筛选容差 `1e-9`。以下采样时间已包含筛选索引和挑选采样中余量最大的点。

| 案例 | 可行采样数 | 缓存点阵后筛选 | 生成点阵＋筛选 | 六次坐标 LP | 当前完整候选 API |
| --- | ---: | ---: | ---: | ---: | ---: |
| 单平面 | 3250 | 0.140 ms | 0.233 ms | 5.100 ms | 6.499 ms |
| 对向平面，只能在平面内滑动 | **0，漏采** | 0.018 ms | 0.110 ms | 4.860 ms | 5.948 ms |
| 三面角落，纯平移 | 813 | 0.029 ms | 0.118 ms | 4.916 ms | 6.096 ms |
| 六向封闭 | 0 | 0.042 ms | 0.131 ms | 5.034 ms | 6.012 ms |
| 理想零间隙轴孔 | **0，漏采** | 0.028 ms | 0.109 ms | 4.775 ms | — |
| 斜轴孔 | **0，漏采** | 0.028 ms | 0.119 ms | 4.999 ms | — |
| 很窄的可行锥 | **0，漏采** | 0.028 ms | 0.114 ms | 5.001 ms | — |

前四例来自实际 M2 几何与接触图，后三例使用明确的解析法线矩阵。轴孔只允许轴向正负方向；斜轴方向为 `(1,2,3)/sqrt(14)`。窄锥由 `±d_x + eps*d_z >= 0`、`±d_y + eps*d_z >= 0` 定义，`eps=tan(0.1°)`。

六次 LP 在两个轴孔、对向平面、窄锥中均找到非零合法方向；六向封闭中没有非零解。因此采样结果为空只能报告 `no_sample_hit`，不能报告 `locally_blocked`。增加采样数不能从根本上解决零球面面积的圆、孤立方向；即使存在很小的正面积，也可能漏掉。不应放大容差来人为填厚允许集合。

这不是“采样计算”和“真实计算”的区别：两者都在计算约束。区别是**在有限方向表内搜索**与**在连续可行域上求解**。固定种子和固定点阵可复现，但不保证完整性。

## 向量化如何实现

对 N 条单位法线、K 个单位方向，最直接的表达为：

```python
# normals: (M, 3)，directions: (K, 3)，都使用 float64 单位向量
minimum = (normals @ directions.T).min(axis=0)
valid = minimum >= -tol
feasible_directions = directions[valid]
```

这是实际的 NumPy 矩阵运算；`@` 可使用底层 BLAS。[NumPy matmul 文档](https://numpy.org/doc/stable/reference/generated/numpy.matmul.html)

`np.vectorize` 是另一回事：它主要包装 Python 函数以便按数组调用，底层基本仍是循环，并不是这种性能优化。[NumPy vectorize 文档](https://numpy.org/doc/stable/reference/generated/numpy.vectorize.html)

推荐逐步采用：

1. 按采样数缓存固定方向表；缓存当前状态下单位化和精确去重后的法线。不要无证据地合并“差不多”的法线，因为可能改变窄锥或退化约束。
2. 法线少时直接使用矩阵乘法。无需为每个方向创建 Python 字典再判断。
3. 法线多时分块，限制中间矩阵内存。6500×2048 个 float64 点积已经约 106 MB，而每个点积只有三项乘加，内存读写开销很明显。
4. 若只需要可行方向及其中最优者，优先筛查有区分作用的法线。方向一旦违反某条约束，立即从后续批次排除；对幸存方向继续检查全部剩余法线。这不会省略任何最终候选的约束。
5. 只计算最终需要的输出。如果要每个被拒绝方向的完整负余量，不能用上述提前淘汰结果替代；应保留完整的分块最小值计算。

脚本包含 `matmul`、`einsum`、限制点积暂存矩阵大小的 `blocked`，以及先检查法线各坐标极值、再按每批 32 条法线筛选的 `progressive`。后者的法线排序与索引复制也计入耗时。

### 约束数量增大后的实测

固定 6500 点，单位法线沿一圈分布，法线的未归一化 z 分量为 0.3。可行采样最终只有约 137 个。默认 BLAS 为 24 线程，以下不改变默认线程数。

| 法线数 | 整张点积表＋筛选 | 逐批淘汰＋筛选 | 直接 SOCP | 等价 QP |
| --- | ---: | ---: | ---: | ---: |
| 32 | 1.474 ms | 0.103 ms | 0.180 ms | 0.130 ms |
| 256 | 5.058 ms | 0.195 ms | 0.513 ms | 0.434 ms |
| 2048 | 47.666 ms | 0.795 ms | 4.366 ms | 3.466 ms |

最后一行提前淘汰约快 60 倍，但这不是通用加速倍数。法线改成接近平行、允许区域较宽后，2927 个采样存活：同为 2048 条法线，在单线程下，密集矩阵 70.205 ms，分块 15.377 ms，逐批淘汰 8.658 ms。幸存方向越多，后续工作越多。

单线程并非总是更快。比如窄区域 2048 行的密集矩阵从默认线程的 47.666 ms 变成单线程 63.787 ms；分块却从 18.504 ms 改善到 11.735 ms。应按实际矩阵尺寸和筛选方式评测，不能简单认为“更多线程”或“单线程”一定最好。可以用作用域限定的 [threadpoolctl](https://github.com/joblib/threadpoolctl) 做这种比较；不要在公共 API 中悄悄永久修改全进程线程设置。

## 最优方向求解采用哪种方法

“最优”在本节特指**局部允许方向的最小角度余量最大**，不代表整条路径最短或装配成功率最高。对于有正角度余量的三维允许域，使用单位法线：

\[
\max_{d,t} t,\qquad Nd\ge t\mathbf1,\quad \|d\|_2\le1.
\]

这是 SOCP。最优 t>0 时最优方向自动具有单位长度，可容忍角度为 `asin(t)`。数值解须复核残差与范数；“全局最优”指此模型的凸优化解，在求解器数值精度范围内，不是几何零误差。[SOCP 形式说明](https://www.cvxpy.org/examples/basic/socp.html)

本次使用 [Clarabel 原生 Python 接口](https://clarabel.org/stable/python/getting_started_py/)，计时包含稀疏矩阵构建、求解和残差检查。CVXPY 适合核对建模表达式，但本次未测量 CVXPY 的建模开销。

| 有正余量的案例 | SOCP | 等价 QP | 最优方向 |
| --- | ---: | ---: | --- |
| 单平面 | 0.131 ms | 0.095 ms | +z |
| 三面角落 | 0.143 ms | 0.096 ms | (1,1,1)/sqrt(3) |
| 窄锥 | 0.144 ms | 0.108 ms | +z |

三者的优化结果均与解析最优余量核对一致。采样只给“采样点中的最优”：单平面的采样最大角度余量为 88.995°，连续最优为 90°；角落为 34.653° 对 35.264°。不能把采样所得第一名称为连续全局最优。

在严格可行的情况下，还可改写成三变量凸 QP：

\[
\min_x \frac12\|x\|_2^2,\qquad Nx\ge\mathbf1,
\quad d=\frac{x}{\|x\|},\quad t=\frac1{\|x\|}.
\]

等价关系来自 `x=d/t`。本机 QP 在这些测试中略快；但可行锥越窄，x 的范数越大，对缩放更敏感。零余量轴孔的这个 QP 不可行，并不意味着轴孔不能轴向运动。建议 SOCP 作为有界、易核对的默认基准，QP 作为经过退化处理与精度验证后的可选实现；不要直接把 QP infeasible 映射为原运动问题 blocked。

### 推荐后续生产流程，尚未接入

1. 准备并验证约束，保留原有 unknown/coverage/near 诊断。没有 active 约束时按任务偏好给方向；没有边界的余量未定义。
2. 先求 SOCP。若得到可靠的正余量，复核归一化方向后即可返回一个首选方向，不需要先做六次坐标 LP。
3. 若最优余量接近零，进入非零可行性与维数判定。此时轴孔、平面内滑动、完全锁死都可能出现零余量，SOCP 本身不能区分。
4. 识别所有可行方向都必须满足的等式并降维，在允许子空间内求首选方向；等价解按任务偏好/明确坐标系的固定规则选择。子空间内余量与三维偏转容忍分别报告。详见[退化处理方案](direction-solver-explained.zh.md)。
5. 需要显示允许区域、寻找后备路径方向时，使用可配置数量的 Fibonacci 点阵，并在低维子空间内改用圆弧采样或轴向端点；先降维解决漏采，增加球面点数不能替代该步骤。
6. 完整路径仍单独检查，首选失败后可以请求其他合法方向。

现有六次 LP 时间主要是当前 SciPy/HiGHS 调用与建模成本，并不是 LP 必须这么慢。可另行评估模型复用和原生接口，但本次没有更换生产 LP 后端。上述 0.13 ms 等数字没有包含通用退化检测，不能用来宣称所有轴孔也能在此时间内完成。

## 库选择与已验证范围

- **NumPy/BLAS**：当前规模的首选；批量点积、分块和提前淘汰已经实测，通常先减少无用运算更有效。
- **Clarabel**：已在指定 Python 中实测 SOCP 和 QP；后续可封装成最优方向后端。
- **Numba**：可用于把点积、比较、提前退出合为编译循环，从而减少临时数组。本轮未安装或计时，不能承诺比本次 NumPy 方案快；首次 JIT 编译与预热必须另计。[Numba 性能说明](https://numba.readthedocs.io/en/stable/user/performance-tips.html)
- **CuPy/GPU**：适合进一步评估大批量问题。本轮未做 GPU 性能比较。对 6500×少量法线的 CPU 小问题，要同时计入数据传输、启动与同步成本，不能由“GPU”推断更快。[CuPy 性能说明](https://docs.cupy.dev/en/stable/user_guide/performance.html)

验证包括球面单位长度与重复生成一致性、密集/分块/逐批筛选结果一致、独立逐方向点积核对、LP 返回方向的全部残差复核、SOCP/QP 一致，以及单平面、三面角落、窄锥、不同法线数圆锥的解析余量对照。未运行完整规划测试套件，因为没有修改生产规划代码；这些测试也不声称覆盖 SDF 误差、静力学或有限运动路径。
