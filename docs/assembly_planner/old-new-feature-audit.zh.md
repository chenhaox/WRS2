## 多方向部分的对应关系

旧 `asp/utils.py:35` 声明 300 个方向；`StabilityAnalyzer` 在 1230 行，1260 行附近把接触力点交给优化器。`asp/stabilitylib/stability.py:212` 的 `getsolution` 调用 330 行的 `soloptfunc_multiprcess`，每个部件、每个六维方向分别求解。它不是所有扰动同时叠加，也不是把整个装配体变换到 300 个空间姿态。

旧版用两个幅值 `kf, kt`，最大化 `kf + kt`，并加 `kt <= radius * kf`；其力和力矩单位不能直接相加。旧文件第一行 `gpu=False`。即使打开其中 JAX 分支，也不等于把 SciPy SLSQP 优化器搬到了 GPU。进程分块、共享最小值和提前退出减少了部分工作，但异常分支和数值状态处理不能直接沿用为可靠证据。

新版 `legacy_coupled` 保留“两个非负幅值、半径耦合、每方向极限”的结构，评分改为 `F + T/L`，明确 `L` 的米单位；**不会与旧混合单位分数数值完全相同**。模型还使用真实质量、16 棱锥和有限支撑，所以不能把新速度对比直接说成旧系统端到端加速倍数。实际 CPU/GPU 同模型基准见[本轮实现与计时](stability-sweep-and-sequence-ui.zh.md)。

旧 `asd3_3_300` pickle 方向集尚未迁移；新版默认方向由确定性公式生成，可直接传入经过验证的 N×6 数组来进行同方向对照。没有声称复用了旧数据文件或逐位复现旧评分。

## 后续建议顺序

1. **M2/M3 联合搜索**：把 M3 的失败原因、阻挡零件、抓取失败与资源冲突返回序列评估器；带输入摘要缓存，尝试其它步骤/抓取。先用当前 stack、gantry 和双臂 floating 做可复现正反例。
2. **辅助抓持生成**：从可达接触区/真实指垫生成有限承载候选，复核机器人、抓取力和交接，再进入资源子集搜索。不能恢复“被持住就省略全部平衡约束”的无限支撑。
3. **序列评分与多解**：选择稳定性、方向容差、路程和资源切换的指标/单位，再输出多条经过 M3 检查的方案。新多方向极限已可调用，暂未成为强制搜索成本，避免每个状态都计算几千个 LP。
4. **旧数据迁移和 CAD/曲面升级**：显式导出可信 mesh/manifest/抓取，不执行未知 pickle；建立同几何、同质量和同摩擦的比较，再增加 B-Rep 与曲面连续配合证据。
